# Local setup

Use a disposable DSH home for installation, persistence and removal tests. Do not
copy credentials or private session logs into it. Use a filesystem with POSIX
permissions — `/tmp` on Linux — because DSH refuses a credentials file readable
beyond its owner.

## Build and package

```bash
npm run check
npm pack --pack-destination /tmp
```

The source of truth is `client/index.mjs`; `lib/client.js` is generated by
`npm run build` and committed; a unit test fails if it is stale.

## Isolated installation

In a separate terminal (do not change the home of your active DSH process):

```bash
export DSH_HOME="$(mktemp -d /tmp/dsh-desktop-ui-e2e.XXXXXX)"
dsh plugin --profile web add /tmp/dsh-desktop-ui-<version>.tgz
# Or, after publication:
# dsh plugin --profile web add dsh-desktop-ui@<version>
```

Starting a test server is a separate, explicit step. It does not update your
normal DSH GUI. Use the URL it prints, not an assumed one.

```bash
dsh web --no-open --port 18766
```

## Reproducible browser test

Add the test-only fixture plugin to the **disposable** profile before starting
DSH. It must be copied outside this package, because DSH rejects one package
served from two loader sources:

```bash
cp scripts/e2e-fixtures.mjs "$DSH_HOME/fixtures.mjs"
cat > "$DSH_HOME/profiles/web/cordis.patch.yml" <<EOF
- insert:
    - id: desktop-ui-e2e-fixtures
      name: $DSH_HOME/fixtures.mjs
EOF
```

The fixture refuses any home outside `/tmp/dsh-desktop-ui-e2e.*` and seeds three
offline sessions on every start — no provider, key or model call is needed. Then:

```bash
dsh web --no-open --port 18766
# in another terminal, with the printed URL (including ?token=…):
DSH_E2E_URL='http://127.0.0.1:18766/?token=…' npm run test:e2e
```

The script starts its own temporary headless Chrome profile, drives it over CDP
with real mouse input, and deletes the profile afterwards. Set
`DSH_E2E_SHOTS=/some/dir` to save screenshots and `CHROME=/path/to/chrome` to
pick a browser. It checks:

- boot, plugin registration, toggle placement above Settings, off by default
- switching into the desktop, taskbar, New session
- sidebar clicks open windows; a session never opens twice
- embedded conversations and one composer per window
- move (size unchanged), resize, minimize, taskbar restore/minimize
- double-click maximize, restore, edge snap
- Tile, Side by side and Cascade layouts, Show desktop
- close keeps the session, reload persistence
- malformed stored state, pruning of unknown sessions, empty state
- narrow layout, toggling off, off state persisting, zero browser errors

After `dsh plugin --profile web remove dsh-desktop-ui` and a restart:

```bash
DSH_E2E_ABSENT=1 DSH_E2E_URL='…' npm run test:e2e
```

## Manual checks not automated

1. Send a real prompt in one window and confirm streaming, tool calls and
   approvals render inside the window while another window is focused.
2. Open the same profile in two tabs and confirm each tab keeps working.
3. Install alongside other sidebar plugins (for example `dsh-workspace-sorter`)
   and confirm both work.
4. Check keyboard access: Tab through window controls and the taskbar.

Keep screenshots, browser profiles, test homes, tokens and logs out of Git and
the npm package. Stop the disposable server when done. Never delete a computed
test-home path without first checking the resolved target.
